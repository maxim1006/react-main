## Как убрать задачу/задачи из релиза?
### TLDR
Команды ниже необходимо выполнять, находясь на релизной ветке.
- Если необходимо удалить задачу, добавленную последней, то выполняем:  
  `git reset --hard <last_commit_hash>`.
- Если необходимо удалить не последнюю задачу в релизе, то выполняем:  
  `git rebase -r --onto <new_parent_commit_hash> <old_parent_commit_hash>`,  
  где `<new_parent_commit_hash>` – хеш коммита задачи перед удаляемой, где `<old_parent_commit_hash>` – хеш коммита удаляемой задачи.
---
> ⚠️ По договоренности с командой было принято решение не использовать `git revert` для отката изменений, т.к. хотим избежать применение реверт коммитов на фича-ветку.

### Пример
Представим ситуацию, что релиз состоит из 3 задач, собранных в следующем порядке:
1. 6229
2. 6599
3. 6581

![](assets/release_revert.png)

Рассмотрим случай, когда необходимо удалить задачу 6581. Так как эта задача была добавлена последней, то можно сбросить все изменения до коммита с предыдущей задачей (в нашем случае, до коммита с 6599). Сделать это можно с помощью команды ниже, использовав хеш коммита `e133bc020`, т.к. это хеш мерж коммита для задачи 6599.
```sh
git reset --hard e133bc020
```
---
Рассмотрим случай, когда необходимо удалить задачу 6599. Так как коммит с этой задачей сам является родительским коммитом для задачи 6581, то просто сбросить изменения не получится. Для того, чтобы исключить все изменения, сделанные в этой задаче предлагается поменять историю коммитов, а именно: в качестве родителя мерж-коммита задачи 6581 необходимо указать мерж-коммит задачи 6229. Таким образом вместо цепочки `6299 -> 6599 -> 6581` можно получить цепочку `6299 -> 6581`, таким образом мерж-коммит для задачи 6599 исключается из истории коммитов релизной ветки. Сделать это можно с помощью команды, использовав хеш мерж-коммита задачи 6229 (задача перед удаляемой) `e42b17ca3` и хеш коммита задачи 6599 (той задачи, которую удаляем) `e133bc020`:
```sh
git rebase -r --onto e42b17ca3 e133bc020
```
---
Также допускаются любые варианты, которые не приводят к появлению обратных изменений в истории коммитов, чтобы не вызывать проблем при обновлении фича-ветки удаленной из релиза задачи на мастер-ветку.
